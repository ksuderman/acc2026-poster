Galaxy on AnVIL

A familiar Galaxy, on AnVIL's secure cloud — researchers run established tools, build workflows and share results without managing command-line software or cloud infrastructure.

Galaxy's core services stay on a small, cost-conscious VM; heavy jobs go to Google Cloud Batch, which provisions right-sized resources on demand and releases them when the work is done.

The pre-built image ships RKE2, Helm, Docker, a configured CVMFS client and fifteen pre-pulled container images, so the boot path does almost no downloading.

Each team changes only what it owns.

For the Terra team

  • No custom VM image to rebuild. Terra supplies instance metadata; the playbook is fetched from Git at boot.
  • No code change to move Galaxy versions. The release is a Helm chart version in the playbook.
  • Nothing hardcoded per workspace. Project, region, network, NFS export and external IP are discovered at runtime.

For the Galaxy team

  • Releases propagate themselves. A galaxy-helm release opens a pull request against the playbook, chart version bumped.
  • Mixins instead of forks. Composable Helm value files deep-merge in order, under user choices rather than over them.
  • Continuous testing launches a real GCE instance on every pull request.
The golden Batch VM image is published once in a shared project and readable by all authenticated users, so a workspace in any project can boot Batch workers from it — the image it runs is independent of the project the job runs in.

Elastic Compute with Google Cloud Batch

2–128 vCPUs
right-sized per job, on demand, then released
On the VM
  • ≤ 1 core / 4 GB
Google Cloud Batch
  • everything larger

Routing is driven by Total Perspective Vortex. Per-tool sizing is declarative, so demanding tools get real hardware without provisioning it in advance:

MetaPhlAn — 16c / 96 GB FastQC — 16c / 64 GB fastp — 8c / 32 GB

Right-sizing is literal. The runner maps requested cores and memory onto a machine shape by memory-per-core ratio and picks the smallest size that fits. Oversized jobs are rejected rather than silently shrunk, so multi-core work really does leave the node.

Reference data comes along. Batch workers boot from the same CVMFS-preconfigured image as the Galaxy VM and bind-mount the Galaxy reference data read-only. Every Batch job carries its Galaxy job ID, so work can be followed from the Galaxy UI into the Cloud Console.

Cost: Paying for Work, Not Uptime

A managed Kubernetes cluster bills continuously for a control plane and a node pool sized for the biggest job it might ever see. A small VM plus Batch bills a modest fixed rate and adds cost only when analyses run.

Projected cumulative cost over one week. The managed cluster climbs whether or not anyone is analyzing data; VM + Batch steps up per job.
~60%
saved at a typical workload
~$57
per week — vs. ~$263 managed
  • Idle is cheap. A Galaxy that is up but unused costs one small VM.
  • Headroom is free. Nothing is provisioned in advance for the largest anticipated job.
  • Effectively unlimited scale. Concurrency is bounded by cloud quota, not a fixed node pool.

AI Co-Scientists: GalaxyAI, Orbit, and Where the Model Runs

One front door, two destinations — a configuration change, not a redeployment.
44 tools
exposed by Galaxy's MCP server — an agent inherits exactly a user's authorization

GalaxyAI is a multi-agent system inside Galaxy: a router hands each question to a specialist — error analysis, tool recommendation, history, training — and every answer is labelled with the agent that produced it.

Agents reach Galaxy through its Model Context Protocol server, which exposes histories, datasets, tools, jobs and workflows as typed operations routed through Galaxy's own service layer. Orbit, running the Loom agent, provides the chat interface — on AnVIL it is packaged as a Galaxy Interactive Tool, launched from the tool panel and running inside the user's own instance.

Where does the model run?

Self-hosted
  • Runs inside the trust boundary; prompts never leave
  • Open weights, no per-token charge — but a GPU billed by the hour, busy or idle
Gemini for Government
  • Stronger reasoning and tool use, nothing to keep warm
  • Per-token pricing, and prompts egress from the boundary
Broader rollout is pending NIH policy guidance on using large language models with controlled-access data. Resolving the policy question, not the engineering, is what determines how GalaxyAI reaches the AnVIL community.
